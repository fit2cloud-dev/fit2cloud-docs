## 1 概述

系统对外提供模型调用能力后，会产生大量调用请求。若无记录，将难以回答"谁在什么时候调用了哪个模型、消耗了多少、成功了没有"等问题。**调用日志**全面记录每一次模型调用的明细，是排查问题、核对用量、分析成本的重要依据。

## 2 列表字段

列表每行对应一次调用记录，主要字段说明如下。

<div style={{textAlign:"center",color:"#8a8f99",fontSize:"13px",margin:"16px 0 8px"}}>表 1  调用日志列表字段</div>

| 字段 | 说明 |
|---|---|
| Request ID | 本次调用的唯一标识，可单击右侧图标复制。 |
| 供应商 / 账号 | 本次调用使用的供应商及上游账号。 |
| 请求模型 | 客户端请求的模型名称。 |
| 上游模型 | 实际转发到上游的模型名称。 |
| 用户 / 用户组 | 发起本次调用的用户及其所属用户组。 |
| 输入 Token / 输出 Token / 总 Token / 缓存 Token | 本次调用各阶段的 Token 用量。 |
| 结果 | 调用结果，如「成功」「客户端错误」「上游错误」。 |
| 状态码 | 上游返回的状态码，如 200、400。 |
| 总耗时 | 本次调用的整体耗时。 |
| 上游累计耗时 | 上游各次尝试的累计耗时。 |
| 调用时间 | 本次调用发生的时间。 |
| 操作 | 单击 **查看** 打开调用详情。 |

:::note[数据为空的字段]
部分调用（如上游返回异常）可能无法采集到 Token 用量，对应字段显示「未知」。
:::

## 3 调用日志筛查

调用日志会随请求量增长而快速累积，若不加以筛选，将难以在大量记录中定位目标。通过筛查，可快速聚焦特定用户、供应商、结果或时间段的记录，便于追踪与排查。

页面顶部提供以下筛查方式：

- **按用户筛选**：通过下拉框仅显示指定用户的调用记录。

- **按供应商筛选**：通过下拉框仅显示指定供应商或账号的记录。

- **按状态码筛选**：通过下拉框仅显示指定状态码（或结果）的记录。

- **按时间维度筛选**：通过「时间维度」选择查看近 7 天、近 30 天等时间范围内的记录。

- **按关键词搜索**：在搜索框中输入 **Request ID、模型、上游模型或错误信息**，可快速定位对应记录。

通过组合使用上述筛查条件，可快速缩小范围、定位到目标请求，完成追溯排查或用量核查。

## 4 查看调用详情

点击某条记录的「查看」，可打开请求详情，查看该次调用的完整信息，包括 Request ID、供应商/账号、请求模型、上游模型、用户/用户组、各项 Token 消耗、结果与状态码等。

当请求出现失败或异常时，详情中的**错误信息**可帮助定位问题原因，例如是调用参数错误、上游连接异常还是配额不足等，从而有针对性地进行排查与处理。

## 5 注意事项

- **结合时间维度排查**：定位历史请求时，请先选对时间范围，超范围记录将不会显示。

- **关注 Token 消耗**：总 Token 与缓存 Token 反映调用成本，用量较大时可结合日志分析是否需要优化。

- **善用筛查快速定位**：记录量大时，建议先按用户、供应商或状态码筛选，再结合搜索精确定位。
