## 1 数据源管理

### 1.1 SQL Server低版本中文乱码如何解决

**问题**：SQL Server 低版本数据源出现中文乱码，添加 charset=GBK 等配置无效怎么办？

**处理方式**：

请区分「连接失败」与「中文乱码」两类问题：

1. **连接失败（连不上旧版 SQL Server）**：数据源配置中提供「兼容低版本」选项。存量数据为保证可用性默认选中，新建时默认不选中。若连接失败，可按需勾选。注意：勾选「兼容低版本」后无法设置编码，**不能**用来解决乱码。
2. **中文乱码**：一般不要依赖「兼容低版本」。`nvarchar` 类型通常不存在乱码；若为 `varchar` 类型且排序规则为 `Chinese_PRC`，可在额外连接参数中添加 `charset=GBK`。另请注意：`varchar` 与 `nvarchar` 不可混用。

若已勾选「兼容低版本」导致无法设置编码，可先关闭该选项后再配置 `charset=GBK`（需确认关闭后仍能正常连接）。

### 1.2 SQLBot 支持跨库或跨数据源查询吗？

**问题**：同一个 Hive 数据源下不同 database 的表，或不同数据源的表，能否联合查询？

**处理方式**：

目前不支持跨库问数，也不支持跨源问数。即使同属 Hive、只是 database 不同，也无法联合查询。该能力与现有架构差异较大，如有需要可到 GitHub 提交 issue，由研发评估后续版本是否迭代支持。

### 1.3 能否不用 Docker 部署 SQLBot？

**问题**：部署 SQLBot 时能否不用 Docker，有没有二进制安装包？

**处理方式**：

目前没有二进制安装包，官方未提供非 Docker 的部署方式。离线安装包同样基于 Docker 运行，且要求 Docker 版本为 v23.0.5 及以上。

### 1.4 SQLBot 支持 Doris 查询 Paimon 数据湖吗？

**问题**：SQLBot 目前是否支持 Doris 查询 Paimon 数据湖 catalog 这类架构的数据源？

**处理方式**：

不支持。如有需要可到 GitHub 提交 issue。

### 1.5 SQLBot 有数据权限控制吗？

**问题**：SQLBot 是否支持数据权限控制，开源版就有还是付费版才有？

**处理方式**：

支持。SQLBot 提供权限配置功能，通过行权限与列权限对工作空间内数据源的数据访问权限进行精细化管理，实现成员间的数据隔离。该功能开源版（社区版）即已提供。

详细配置步骤请参阅[权限配置](../user_manual/permission.md)

### 1.6 SQLBot 支持 Mac 部署吗？

**问题**：能否在自己的 Mac 上部署 SQLBot，有没有 Mac 的部署文档？

**处理方式**：

可以。源码运行支持 macOS（x86 与 arm64），按源码运行方式部署即可。

详细步骤请参阅[源码运行](../installation/source_run.md)

### 1.7 SQLBot 只能连接本地数据库吗？

**问题**：SQLBot 是否只能连接本地数据库，能否连接其他类型的数据源？

**处理方式**：

不是。SQLBot 支持多种类型的数据源，包括 OLTP 型数据库（MySQL、SQL Server、Oracle、PostgreSQL、达梦、Kingbase）、OLAP 型数据库（ClickHouse、Apache Doris、Elasticsearch、StarRocks）、数据仓库/数据湖（AWS RedShift、Apache Hive）以及数据文件（Excel/CSV）。

## 2 智能问答与助手

### 2.1 示例SQL因表召回限制未生效怎么办？

**问题**：编写了示例 SQL，但因涉及表数量较多，部分表未被召回导致 SQL 执行失败，如何处理？

### 2.2 DataEase 3.0 能接入 SQLBot 吗？

**问题**：DataEase 3.0 的系统设置里找不到 SQLBot 接入项，是不支持对接吗？

**处理方式**：

DataEase 3.0 目前不支持与 SQLBot 对接，原生已不再支持；如有需要可到 GitHub 上提 issue。

SQLBot 接入 DataEase 要求：SQLBot v1.1.3 及以上版本，DataEase v2.10.13 及以上版本。

配置步骤请参阅 [DataEase 接入](../dataease_integration.md)

### 2.3 SQLBot 可以嵌入到网页中吗？

**问题**：SQLBot 能否嵌入到自己的网页/系统中使用？

**处理方式**：

可以。SQLBot 支持通过【小助手嵌入】（含基础应用、高级应用）和【网页嵌入】三种方式嵌入到外部系统页面中，每种模式都支持「浮窗嵌入」和「全屏嵌入」两种呈现方式。三类方式按权限划分：基础应用为游客/员工权限、使用 SQLBot 数据源；高级应用为宿主权限、使用宿主数据源（API 接口）；页面嵌入为 SQLBot 权限、使用 SQLBot 数据源。

详细步骤请参阅[嵌入式对接](../embedding_integration.md)。

### 2.4 SQLBot 对本地模型参数有要求吗？

**问题**：私有化部署时，接入 7B、14B 这类小参数模型能正常问数吗，模型需要训练或优化吗？

**处理方式**：

推荐本地模型参数最少 32b 起步。低于该参数的模型（如 7b、14b）可以接入试用，但效果不太能保证；模型无需自行训练。若本地模型效果不理想，更推荐接入在线大模型。

### 2.5 DataEase 接入 SQLBot 需要提前处理数据吗？

**问题**：对接 DataEase 数据源后，在 DataEase 问答这块需要提前处理数据吗？

**处理方式**：

不需要提前处理数据。高级小助手的原理是把当前 DataEase 数据源信息以配置项方式提供给 SQLBot，因此只需保证 SQLBot 能访问到 DataEase 当前使用的数据源即可；若访问不通，问答就会出现问题。

配置步骤请参阅 [DataEase 接入](../dataease_integration.md)

### 2.6 新建对话能否不选数据源？

**问题**：每次新建对话都必须选一个数据源才能开始，能否跳过选择、默认使用某个数据源？

**处理方式**：

目前不支持跳过数据源选择，专业版同样不支持。每次新建对话都需先选择一个数据源，点击【确认】后才能进入问数。如需变相实现该效果，可走 MaxKB 调用 SQLBot MCP 这条路径。

### 2.7 SQLBot 问数有表数量限制吗？

**问题**：问数时提示涉及表过多，是不是不能超过 30 张表？

**处理方式**：

没有硬性拦截。表过多时前端会提示「选择数据表过量」，但点击确认后实际不会拦截，仍可继续问数。

### 2.8 SQLBot 是免费还是付费产品？

**问题**：SQLBot 到底是免费还是付费产品，有版本区别吗？

**处理方式**：

SQLBot 有开源版本和商业版本，社区版是完全免费的。商业版本为专业版，包含企业版增强包和基础级的原厂企业级支持服务，支持单机/冷备部署，价格为 3 万/套。

企业版功能与版本说明请参阅[商业版本](../buy.md)

### 2.9 SQLBot 对模型上下文窗口有要求吗？

**问题**：接入大模型时老是提示上下文超限，SQLBot 推荐的模型上下文窗口大小是多少？

**处理方式**：

推荐模型上下文窗口至少 128k。SQLBot 需要向模型传入较多表结构和自定义提示词，窗口过小容易触发上下文超限。上下文轮数没有硬性规定，需结合【参数设置】中的「上下文记忆轮数」自行调控。

### 2.10 DataEase 接入 SQLBot 校验失败怎么办？

**问题**：DataEase 和 SQLBot 两边都配置好了、端口也通，为什么第三方嵌入校验还是失败？

**处理方式**：

若 DataEase 以 HTTPS 方式访问，浏览器不允许在 HTTPS 页面里发起 HTTP 请求，会导致校验失败。改用 HTTP 加 IP 端口的方式访问 DataEase 后再校验。

另外，DataEase 与 SQLBot 的版本差异也可能导致嵌入失败，需确认版本满足：SQLBot v1.1.3 及以上、DataEase v2.10.13 及以上。

详细配置步骤请参阅 [DataEase 接入](../dataease_integration.md)

### 2.11 问数响应约1分钟正常吗？

**问题**：从提问到输出结果差不多要1分钟，这个速度正常吗？

**处理方式**：

问数响应时间与所选模型有关，可更换模型后重试。
